## 2. 遊戲 build 交付規範

### 2.1 HTML5（Web）版 — itch.io 硬性限制
- [ ] 打包成 **ZIP**。itch.io **只接受 zip**，`.rar` / `.7z` / `.tar.gz` 一律不行。
- [ ] `index.html` 必須在 **zip 的根目錄**，不能包在一層資料夾裡。
- [ ] 解壓後**檔案數 ≤ 1000 個**。
- [ ] 解壓後**總容量 ≤ 500 MB**、**單一檔案 ≤ 200 MB**。
- [ ] **含路徑的檔名長度 ≤ 240 字元**。
- [ ] 檔名使用 **UTF-8** 編碼。
- [ ] **所有資源用相對路徑**。以 `/` 開頭的絕對路徑在 itch.io 的 CDN 子目錄下必定失敗。
- [ ] **檔名大小寫完全一致**。itch.io 伺服器區分大小寫，Windows 本機能跑不代表線上能跑（典型症狀：Chrome console 出現 `net::ERR_ABORTED 403`）。
- [ ] 不得請求任何非 HTTPS 的外部資源（排行榜 API 也必須是 https）。
- [ ] 不要嘗試存取資料夾路徑（結尾是 `/`）— 會回 403 而不是 404。

### 2.2 HTML5 版 — Godot 專屬設定（本專案最容易踩雷的區段）
> ✓ 已確認：`export_presets.cfg` 的 `variant/thread_support=false`（單執行緒匯出，符合下方
> SharedArrayBuffer 那條的預設建議）；Run in Browser 於 08-07 驗證可正常運作（見
> HANDOFF_ARCHIVE.md）。以下維持待驗證：

- [ ] 確認 Godot 版本與 **export templates 版本完全一致**（4.6.0 的 template 不能配 4.6.1）。
- [ ] Renderer 設為 **Compatibility（OpenGL / WebGL2）**——`export_presets.cfg` 未見顯式 renderer
      覆寫設定。08-07 的 Run in Browser 能跑代表當時匯出用的是相容設定，但正式匯出前建議在
      編輯器 Project Settings 目視確認一次 Rendering Method，不要只憑舊紀錄推定。
- [ ] **不要用 C#**（Web 匯出不支援）。GDScript 為準。（現況：全專案僅 `.gd`，符合，列著提醒未來別引入）
- [ ] 只有在確實需要多執行緒時，才在 itch.io embed 設定勾「SharedArrayBuffer support」。**要清楚知道代價**：
  - 依賴 `coep:credentialless`，Safari 與 Firefox for Android 支援不完整；
  - 開啟後會影響同頁面的第三方內容（例如 YouTube 嵌入、部分情況下的下載按鈕）。
  - 對一款 2D 像素遊戲，**幾乎沒有理由開啟**。
- [ ] 音訊：Godot 4.3+ web 預設 Sample 模式（低延遲，但不支援 AudioEffect / 混響 / 程序化音訊）。若遊戲用到音效總線效果，需改為 Stream 模式並實測延遲。（現況：專案零音效系統，暫不適用，加音效時才需要處理）
- [ ] 匯出後**本機用 HTTP server 測試**（直接雙擊 `index.html` 一定失敗；Godot 編輯器的「Run in Browser」會自動起一個設定正確的 server）。
- [ ] 確認 itch.io CDN 會自動 gzip `.wasm` / `.pck` / `.js` / `.html` / `.css` — 不需要自己預壓縮成 `.gz`（若真的預壓縮成 Brotli，副檔名必須是 `.br`）。
- [ ] 記錄首次載入的實際傳輸大小與載入秒數（見 §8 效能門檻）。

### 2.3 下載版
- [ ] 每個平台各一個 zip（Windows / macOS / Linux 分開）。
- [ ] 檔名含版本號：`GameName_v0.1.0_win64.zip`。
- [ ] zip 內附 `README.txt`：安裝方式、操作說明、系統需求、已知問題、聯絡方式、免責聲明。
      （尚未撰寫——待實際打包時一併寫，內容可直接沿用 `SpikeConfig.DISCLAIMER_TEXT_BY_LANG` 與遊戲操作說明）
- [ ] 無 DRM、無安裝器夾帶廣告、無第三方登入牆。
- [ ] 檔案**直接上傳到 itch.io**，不要用 Google Drive / MEGA 外連（違反 itch.io 品質指南）。
- [ ] macOS / Linux 版**除非真的在該系統上跑過，否則不要上架、也不要在 metadata 勾該平台**（itch.io 明文要求平台標記必須實測；亂勾會被下架索引）。

## 4. 商店頁面美術素材（規格是硬的，照做）

| 素材 | 規格 | 備註 |
|---|---|---|
| **Cover image（封面）** | **比例 315:250**；315×250 是最低，建議上傳 **630×500** 同比例 | 沒有封面 → **不會被 itch.io 索引**。可用 GIF，但**不得有閃爍 / 誘發光敏性癲癇的效果** |
| **Screenshots** | 建議 **3–5 張**，尺寸不限 | 建議用遊戲原生解析度（1280×720）的 PNG。可用 GIF |
| **Banner（頁面標題橫幅）** | 無固定尺寸，theme editor 上傳 | 上傳後會**取代**頁面上的文字標題。可用半透明 PNG 或 GIF |
| **Background image** | 無固定尺寸 | 可做垂直重複的紋理背景 |
| **Embed 背景圖（HTML5 專用）** | 等同 embed viewport 尺寸 | click-to-play 按下前顯示的畫面，可再疊一層漸層色 |
| **Trailer** | YouTube / Vimeo / Sketchfab 連結 | 有 trailer 才會啟用瀏覽列表上的「Watch trailer」按鈕。**務必設為公開**，用無痕視窗驗證 |

- [ ] 上述素材全部產出並命名歸檔。
- [ ] **重要陷阱**：HTML5 專案頁預設是**單欄版面且隱藏 screenshots 欄**。必須在 theme editor 把 Layout > Screenshots 改成 `Sidebar`，**或**把圖片直接嵌進描述文字裡。否則你做的截圖沒有人看得到。
- [ ] 封面圖不得使用 hololive 官方美術素材、官方 logo、官方立繪。全部自繪。
- [ ] 配色 / 字體在 theme editor 設定完成，與遊戲美術一致。
- [ ] 用手機寬度檢查頁面版面（itch.io 頁面是 responsive，但重度客製化容易在小螢幕爆掉）。

- [ ] 後端 schema 預留可加欄位的空間（用 JSON metadata 欄位而非固定欄位）。

### 11.5 發佈流程（itch.io 端的更新機制）
- [ ] **絕對不要為了新版本開新的專案頁面。** 新頁面不會帶走既有的下載數、評分、留言與收藏，itch.io 也明文把「重建頁面刷曝光」列為違規。
- [ ] 網頁版標準更新流程：上傳新版 zip，然後刪掉舊版 zip。
- [ ] 若更新頻繁，評估改用 **butler**（itch.io 官方 CLI，現在也內建在 itch app 的 Upload 分頁）：
  - 推送到固定 channel（如 `win-stable`、`html`），第一次全量上傳，之後每次只上傳與前一版的差異；使用 itch app 的玩家更新時也只下載差異 patch。
  - 推送完成即可下載；itch.io 後端會在背景用 bsdiff 重新產生更小的最佳化 patch，處理期間玩家仍可用預設 patch 更新，不會被卡住。
  - **HTML channel 的坑**：用 butler 推網頁版時，若 zip 檔名改變，itch.io 上的「This file will be played in the browser」勾選可能需要重新手動設定。**固定 zip 檔名**可以避開這件事。
- [ ] 每次更新都發一篇 **devlog**（追蹤者會收到通知、devlog 會被索引，是免費的回訪流量）。
- [ ] 網頁版與下載版**同時更新**，或在頁面明確標示兩者版本差異。
- [ ] **保留可回滾的能力**：每個發佈版本的 build 產物在本機歸檔（含 export preset 設定）。線上出事時能在 30 分鐘內把上一版推回去。
- [ ] 更新內容若包含「玩家可能不喜歡的變更」（削弱、移除內容），在 devlog 與遊戲內公告事先說明。

### 11.6 網頁版的快取問題（更新後玩家還在跑舊版）
> ✓ 遊戲內版本號顯示已完成（設定頁）。以下仍待實際發版時才能執行/驗證：

- [ ] 更新後**用一般視窗（非無痕）** 重新開啟遊戲頁面，確認拿到的是新版——這是玩家的真實情境。無痕視窗一定會拿到新版，測不出問題。
- [ ] **建議本專案不要啟用 PWA / Progressive Web App 匯出選項**，除非真的需要離線遊玩。Godot 的 PWA service worker 採 cache-first 策略、以匯出時間戳做為快取版本，處理不當時玩家會持續載到舊的 `.pck`。
- [ ] 若堅持啟用 PWA：每次更新**必須完整 Export Project**（不能只重新產生 `.pck`），否則 service worker 版本不會更新、玩家端快取不會失效。
- [ ] 若排行榜或存檔格式有變更，遊戲啟動時檢查版本，對跑在舊版的玩家顯示「請重新整理頁面以取得最新版」。

### 11.7 每次補丁的固定回歸測試劇本
> 尚未有 v1.0 正式版可比對，黃金存檔要等第一次正式發佈後才有意義建立；先保留清單，不預先
> 建立空殼——空的「黃金存檔」不能驗證任何事。

- [ ] 建立一組**黃金存檔（golden saves）** 並納入版控，每次更新前都拿它們測：
  - `new_game`：全新開檔
  - `early`：v1.0 初期進度
  - `mid`：中期，部分商品已購買
  - `complete`：已通關／全解鎖
  - `edge`：極端值（滿背包、最大金幣、最高等級、所有設定改成非預設）
- [ ] 每個黃金存檔在新版都要通過：**能載入 → 不 crash → 既有進度一項不少 → 新內容正確出現 → 存回去再讀一次仍正確**。
- [ ] 每次黃金存檔本身也要更新一份新版產生的樣本，加進集合裡（下次更新就有更多歷史版本可測）。
- [ ] 新增音效專用檢查：音量匯流排歸屬正確、玩家原有的音量／靜音設定沿用、網頁版總下載量沒有暴增。
- [ ] 新增商品專用檢查：舊存檔看得到新商品、價格與解鎖條件正確、不影響既有已購買項目。
- [ ] **容量監控**：每次更新後記錄網頁版解壓後的檔案數與總容量，逼近 itch.io 的 1000 檔／500MB 上限前就要處理（音效與圖片累積得比想像中快）。
- [ ] 至少在 Chrome 與 Firefox 各跑一次（§8 的測試矩陣可簡化，但不可跳過）。
- [ ] 發佈後 24–48 小時密切留意留言區與社群回報，準備好熱修。

### 11.8 每次更新都要重跑的 hololive 合規檢查
> COMPLIANCE.md／THIRD_PARTY_LICENSES.md 已建立，以下清單就是「每次更新要重跑」的動作
> 本身，保留不動：

- [ ] 新增任何角色、美術、音樂、音效 → **重新過一次 §6 的紅線清單**。
- [ ] 更新 `CREDITS.md` 與 `THIRD_PARTY_LICENSES.md`（新素材的授權來源）。
- [ ] 確認新增內容**沒有引入任何變現**（不能因為「只是加個小額打賞」就破功）。
- [ ] 大版本更新前，重看一次官方指南頁面並更新 `COMPLIANCE.md` 的檢視日期——指南可無預告修改。
